━━━ A. 命令系统规范化 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A1  [必做]  删除 `v` / `verbose`
    原因：motion 状态已在 sensors.csv 5Hz 记录，完全冗余；
          verbose 输出还占用 HC-12/WebConsole 带宽
    风险：丢失实时 motion 观察能力（改看 SD 事后分析）

A2  [必做]  `g` 精简：删除 printDebug()（D1/D2/PROM/采样计数/错误数）
    原因：纯硬件排错用，传感器确认正常后无用
    建议：另存一个 `diag` 隐藏命令备用

A3  [可选]  `g` 在 TEST 模式下拒绝
    原因：SD 在记，命令冗余且占 HC-12 带宽
    风险：无法在 TEST 中快速看当前值

A4  [必做]  HC-12 上的 `g` 输出压缩成 `d<cm>f<cm>l<cm>r<cm>b<V>` 一行
    原因：完整文本 ~200 字节；压缩后 ~25 字节；
          9600 bps 下发送时间从 2 秒降到 0.03 秒
    风险：需要 PC 端解析

A5  [必做]  `mark` 命令保留 UTF-8 / 大小写（跳过 toLowerCase）
    原因：中文 `mark 入水第一阶段` 理论上可能被 tolower() 破坏
    风险：改动小，零风险

A6  [建议]  `stat` 加入 HC-12 白名单
    原因：无线调试时可以查 SD 进度

A7  [必做]  `l<N>` 加安全保护：`l0` 拒绝，超出合理范围（0-500cm）拒绝
    原因：串口噪声让 `labc` → toFloat()=0 → 机器人浮到表面
    风险：正常定深 0cm 的需求不存在

A8  [可选]  `q` AUTO 切换加二次确认（需要 `qy` 或类似）
    原因：误触进入自动导航

A9  [建议]  `ESP<NNN>` 信道号范围检查 001-127
    原因：HC-12 只支持这个范围

A10 [低优先级]  长命令别名统一：给 `q`/`mt`/`md`/`stat` 也加英文别名


━━━ B. 通信资源优化 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

B1  [最高优先级]  TeeStream 拆掉 HC-12
    g_dbg 只写 USB+Web；HC-12 只发 ACK/命令响应/压缩传感器数据
    原因：当前每条 debug 都经 9600bps HC-12 发，单行阻塞 loop 80ms；
          RF 信道长期被调试占用
    风险：HC-12 上看不到启动日志（但 USB/Web 仍有）

B2  [建议]  SD 日志搬到 Core 1 + FreeRTOS queue
    原因：SD GC stall 200-500ms 会直接卡主 loop，影响运动控制节拍
    风险：改动中等；队列满时旧数据会丢

B3  [待定]  HC-12 TX 改成环形缓冲 + 后台 task
    原因：HC-12 TX 缓冲满时 println() 阻塞 loop
    建议：B1 做完后再评估

B4  [建议]  超声波降频到 25Hz（当前每 loop 轮询，~100Hz）
    原因：SPI 带宽浪费；25Hz 已够（10cm 分辨率下 4 km/h）
    风险：对极高速运动响应变慢

B5  [不做]  Web 控制台改 SSE（Server-Sent Events）
    原因：收益小，改动大


━━━ C. 数据可靠性（旧建议未拍板） ━━━━━━━━━━━━━━━━━━━

C1  [条件]  FLUSH_EVERY_N_ROWS 从 5 改为 1（每行 flush）
    原因：断电窗口从 1 秒降到 0.2 秒
    风险：SD 写入频率 ×5，可能加剧 GC stall
    条件：如果 B2（SD→Core 1）做了就改；否则保持 5
